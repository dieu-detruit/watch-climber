# Watch Climber：ルート登録不要の登山記録

## 追加で合意した方針

ユーザーは経路確認にYAMAPを使う。こちらは補完する楽しさを主目的に、標高の推移・登るペース・心拍・100mごとの累積上昇の節目を中心にする。軌跡は補助画面。ナビゲーションと実地図は今回の優先事項から外す。実装判断は任されている。

## 目的と対象

翌日の白馬五竜方面の登山で、現在地と標高を手首で確認したい。
対象は Apple Watch SE 3（GPS）、watchOS 26.5。
予定ルート・宿泊地点は未定。これらを入力せずに使えることを必須とする。
まず Web で画面と操作のフィードバックを受け、その後にネイティブ版を実装する。

## 採用する進め方

最初はブラウザで動く Watch サイズのインタラクティブな試作を作る。
模擬 GPS・高度・心拍データを使い、登山中の操作と表示を確認する。
ブラウザの実 GPS を先に実装する案もあるが、Watch のセンサや画面消灯中の
記録を検証できないため、初回は画面と状態遷移に集中する。
ネイティブ版を先に作る案は、Web でフィードバックしたいという希望に合わない。

## Web 試作の範囲

- React / TypeScript / Vite を使い、このリポジトリ内でローカル起動する。
- 日本語表示、黒背景、大きな数字、押しやすい操作領域。
- 40mm / 44mm 相当の画面サイズを切り替えて確認できる。
- 全画面で「デモ」を明示する。数値や軌跡を実測・実在の登山道と誤認させない。
- Web 試作は行程を入力せず、記録開始だけで動く。

### 画面

1. **状況**：現在の標高を主役に、経過時間・距離・累積上昇・心拍を表示。
2. **軌跡**：開始点・現在地・記録済みの軌跡・北の向き・位置精度を表示。
   初回は模擬座標を使った軌跡図とし、「背景地図なし」と明示する。
   地形や山名を確認できる実地図はネイティブ版に向けた別の設計項目とする。
3. **記録**：開始・一時停止・再開・終了と、終了後の記録概要。
   終了は確認操作を挟み、誤タップによる終了を防ぐ。

画面切り替えはスワイプとクリック可能なタブの両方に対応する。
ブラウザの外側にデモ操作を置き、「歩行・休憩・GPS不良・心拍取得不可」を
切り替えられる。これはネイティブの製品画面には含めない。

### 記録と欠損値

- 状態は未開始・記録中・一時停止・終了の4つ。
- 一時停止中は記録時間・距離・累積上昇・軌跡への追加を止める。
- GPS不良時は最終取得位置と更新時刻を残し、現在の測位が不良と表示する。
  不良な点を距離・累積上昇の集計に使わない。
- 未取得の標高や心拍はゼロではなく「—」で表示する。
- 累積上昇は小さな高度変動を除外し、センサノイズを登りとして加算しない。
- デモ記録をブラウザの localStorage に保存する。再読込後に復元した記録は
  一時停止として扱い、ページを閉じている間に計測したようには表示しない。
- 保存失敗時は画面上に通知し、保存済みと表示しない。

## ネイティブ版への引き継ぎ

SwiftUI と Core Location を基本とし、GPS計測と記録はWatch側で完結させる。
高度・方位・心拍は対応APIと許可の状況を確認して取得する。
位置と記録は通信なしで保存できる設計にする。
実地図と圏外用地図の準備は、軌跡のローカル保存とは別に扱う。
予定ルートが後から判明しても、記録開始の必須入力にはしない。

画面消灯中の継続記録、ワークアウト連携、バッテリー消費、測位精度は
ネイティブ実装と実機で検証する。Web試作の動作をその保証にはしない。
泊まりを挟む運用は登山区間ごとに記録を終了・保存し、翌日に新しく開始できる形を基本とする。

brain-dump の XcodeGen / Codemagic 構成を踏襲し、シミュレータテストと
署名付きアーカイブ・TestFlight配布を分ける。
既存アプリのBundle IDは流用せず、今回用の登録と署名設定が必要。
Webへのフィードバックが済むまでは、ネイティブ製品コードと配布設定は実装しない。

## 検証と完了条件

- 行程未入力で開始・一時停止・再開・終了・記録概要の確認ができる。
- 位置・標高の変化をデモで再現し、3画面で一貫した値を表示する。
- GPS不良時に位置を更新したように見せず、距離へ異常な値を加算しない。
- 欠損値、保存エラー、再読込時の状態が確認できる。
- 状態遷移と距離・高度の集計をテストし、型チェックと本番ビルドを通す。
- 小さい画面で主要表示・操作が欠けないことをブラウザで確認する。
- 起動方法をREADMEに記載し、ユーザーに試作の確認手順を伝える。
